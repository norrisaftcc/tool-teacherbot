## Run, Change, Inspect, Revise

You have mapped the responsibilities in your own prototype. Before you migrate it, work in one more controlled environment where you can change a Flask structure, run the request flow, and see what your decision changes.

Build question

**Can a choice make one screen work while weakening reuse, state, rule enforcement, or traceability somewhere else?**

### What the lab gives you

The controlled lab uses a simulated Flask sandbox so you can focus on architecture and behavior before working in Codespaces. You will inspect a small request flow, choose a structural change, run the scenario, inspect the consequence, and revise.

**1. Thin route**
Test whether the two-attempt rule remains reusable outside Flask.

**2. Interrupted state**
Test what survives when one request ends and another begins.

**3. Rule enforcement**
Try the Memory Bank limit through more than one entry path.

**4. Traceability**
Decide what makes a working implementation defensible and reviewable.
