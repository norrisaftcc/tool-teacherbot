CTS-285 · Module 6 · Graded Evidence

## Code Review Given

Review another implementation against behavior and evidence. The grade reads the quality of the review you give, not the quality of the code you receive.

Outcome

**MLO 6.2 → CLO 4, CLO 5:** evaluate implementation behavior against acceptance criteria and source evidence; distinguish defects, decisions, and unresolved gaps.

### Review target

Use the implementation assigned by your instructor. If a partner is unavailable, use the supplied M6 review target. The fallback carries no penalty and needs no explanation.

### Your review file

Create `docs/reviews/m6-code-review-given-<github-username>.md`. For each meaningful finding include:

1. **Observed behavior:** what you actually ran or saw, including values when possible;
2. **Evidence:** acceptance criterion, test, source page, requirement, or decision that bears on it;
3. **Classification:** defect, decision, or gap;
4. **Next move:** the smallest reasonable action to resolve, record, or escalate it.

Include at least one finding based on **running** the implementation, not only reading it. Do not pad the review with style comments to increase the finding count.

**Submit in Canvas:** one link to the review file or pull-request review evidence in GitHub. No duplicate file upload.

How this is graded

**6 points:** evidence-based observation/classification 3, source-grounded reasoning/actionability 3.
