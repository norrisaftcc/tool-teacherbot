## Sprint 2 Contribution

Submit the GitHub evidence for the Sprint 2 work attributable to you. This sprint adds one expectation to the pattern you used in M6: your evidence must show what happened to previously protected behavior while the system changed.

### Submit one GitHub evidence link

Use a pull request, branch comparison, or stable repository location that exposes your own implementation and test history. Do not upload duplicate code to Canvas.

### Your evidence must show

1. **Your Sprint 2 contribution:** work attributable to you and traceable to the sprint scope.
2. **Regression protection:** evidence that previously protected behavior was run against the changed system and any failures were investigated before tests or code were revised.
3. **Sprint 2 quality accounting:** your slice evaluated against the current Definition of Done, including honest handling of any not-met result.

**Do not earn credit by deleting the evidence of a regression.** If an old test no longer represents required behavior, the repository should make the reason for changing that test visible.

**Points:** use the same 10-point common contribution architecture as Sprint 1 unless course-wide reconciliation changes it.
