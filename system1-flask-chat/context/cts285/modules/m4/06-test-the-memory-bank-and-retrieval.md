## Test the Memory Bank and Retrieval

The Answer Flow Lab tested behavior over time. Now shift the lens. A system can behave correctly in the moment and still fail later if its relationships, constraints, or stored evidence cannot support what users need to retrieve.

**Think beyond the screen.** A good interface cannot recover information the system never represented, preserved, or related correctly.

### The system requirements

DataMan allows a curator to build a Memory Bank practice set with up to 10 problems. A problem may need to appear in more than one set. After a learner completes work, a curator must be able to retrieve meaningful evidence about learner results and missed problems later.

### What you are testing

- **Relationships:** can problems and sets be represented without locking one problem to only one set?
- **Constraints:** is the 10-problem limit enforced as a real business rule rather than only a screen behavior?
- **Persistence:** is enough attempt/result evidence preserved after the learner session ends?
- **Retrieval:** can the curator later ask a real question and get an answer from the data the system kept?
