## Capstone Handoff Package

Submit the GitHub location that anchors your own contribution to the capstone handoff. The shared package is context. This grade reads what you personally validated, created, hardened, or resolved and whether your evidence improves the package the next course receives.

### The package must make these components findable

- pod provenance and hardened working agreement;
- product handoff status according to the approved cross-course decision;
- validated backlog;
- validated wireframes/design evidence;
- design brief draft;
- design-consult record/contact status;
- seeded risk register and open dependencies;
- handoff manifest/exit checklist.

### Your individual submission

Submit one GitHub link that makes your work easiest to inspect. Your evidence should show:

1. **What you owned:** identify the handoff component(s) for which you were the primary student owner.
2. **What changed:** show what you kept, hardened, created, or left explicitly unresolved.
3. **Why:** connect the action to prior course evidence, a handoff requirement, risk, dependency, or later sprint finding.
4. **What the capstone receives:** make the final location/status obvious to a reader entering the next course.

**Do not duplicate the package in Canvas.** Canvas records the academic submission link; GitHub remains the handoff source of truth.

### A missing external response is not missing student evidence

If the design-consult contact or another external dependency remains pending, the package should show the request/status, fallback used if applicable, and next responsibility. You are not graded on another person responding.

How this is graded

**12 points:** individual ownership 3, evidence-based handoff decisions 3, package traceability/readiness 3, explicit unknowns/dependencies 3.
