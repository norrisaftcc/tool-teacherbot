CTS-285 · Module 8

## Build the Capstone Handoff

Product delivery stops here. Module 8 turns the evidence you already built into an explicit package the capstone can inherit without spending its first weeks rediscovering the project.

Driving question

**What does the next course need to inherit so the team can begin capstone work without rediscovering the project?**

### Module learning outcomes

MLO 8.1 → CLO 3, CLO 5 — Validate Capstone Handoff Readiness

Audit prior project evidence for completeness, traceability, currency, and unresolved risk; distinguish reusable artifacts from items that must be revised or created for the capstone handoff.

MLO 8.2 → CLO 3, CLO 5 — Produce the Capstone Planning Package

Assemble the required pod, backlog, design, working-agreement, consult, and risk evidence into a coherent handoff package while preserving individual accountability.

MLO 8.3 → CLO 5 — Defend the Handoff and Name the Unknowns

Present and justify the package's key decisions, risks, dependencies, and open questions so CSC-289 can act on the evidence rather than diagnose the project from scratch.

### The handoff package

By the end of the module, the package must make these components findable:

- formed pod/team with provenance;
- hardened working agreement;
- the pod's capstone direction, including decisions intentionally left open for the receiving course;
- validated user-story backlog;
- wireframes/design evidence;
- design brief draft;
- design-consult contact/record;
- seeded risk register;
- exit checklist matching the capstone entry expectations.

### Reuse before you recreate

Most of the package should come from work you already did. Requirements, backlog, acceptance criteria, wireframes/design evidence, sprint records, tests, and review findings do not become more valid because you copy them into a new document.

Keep

Current and ready to hand forward.

Harden

Useful, but needs revision or context for the capstone.

Create

Required by the handoff but not yet present.

Resolve

A decision or dependency must be settled before handoff.

How this is graded

The package is shared context. Your grade is still based on evidence attributable to you. Module 8 does not introduce a group grade at the finish line.
