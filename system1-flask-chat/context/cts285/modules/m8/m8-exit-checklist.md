# CTS-285 Exit Checklist — CSC-289 Handoff

Use this checklist from the receiving course's point of view. A row can be ready even when it names an unresolved decision; it is not ready when the decision is hidden, ownerless, or impossible to locate.

| # | Handoff check | Ready when... | Path / evidence | Receiving action if any |
|---|---|---|---|---|
| 1 | Pod provenance | The arriving pod status is explicit: intact, reduced, dissolved, onboarding hire, or solo by exception. | | |
| 2 | Working agreement | The hardened agreement is linked and current for the handoff. | | |
| 3 | Capstone direction | Problem space, stack starting point, scope ambition, and deliberately open decisions are recorded. | | |
| 4 | Backlog status | The DataMan backlog is clearly labeled as prior-course evidence/worked example rather than silently presented as the capstone backlog. | | |
| 5 | Design evidence | Wireframes/interaction evidence are linked, current, and their reuse/adaptation status is clear. | | |
| 6 | Design brief | The design brief is linked and its current status is understandable without reconstructing the semester. | | |
| 7 | Critique record | The required instructor critique is recorded; optional external feedback is included only if it exists. | | |
| 8 | Risk register | Seeded risks and dependencies are visible, prioritized enough to act on, and not presented as resolved when they are not. | | |
| 9 | Manifest and links | The handoff manifest points to the final source artifacts and every link/path opens correctly. | | |
| 10 | Open decisions | Every known unresolved risk, dependency, or product decision has current evidence plus a named receiving owner/action. | | |

## Pass rule

The package is ready when a person entering CSC-289 can locate the evidence, understand what is current, distinguish reusable evidence from worked examples, and see the next decision without asking the CTS-285 student to reconstruct the semester from memory.

An explicit unknown can pass. A hidden or ownerless unknown cannot.
