CTS-285 • Module 3 • Product Decision Evidence

## Product Owner Decision Record

Submit the decision record generated by the M3.5 Product Owner Sprint Simulation. Your record should show how you built a release slice, responded when capacity and release constraints changed, and made a defensible tradeoff.

Your artifact

**What to submit.** After completing **M3.5 — Product Owner Sprint Simulation**, generate your decision record and save it in your CTS-285 GitHub repository at:

`docs/decisions/m3-product-owner-decision-record.md`

### Submission steps

1. Complete both rounds of the Product Owner Sprint Simulation.
2. Generate the Product Owner Decision Record at the end of the simulation.
3. Copy the generated Markdown into `docs/decisions/m3-product-owner-decision-record.md`.
4. Commit the file to your CTS-285 GitHub repository.
5. Open the rendered Markdown file in GitHub and confirm that the record is complete and readable.
6. Submit the direct GitHub URL to that file in Canvas.

Caution

**Do not add a separate essay.** The decision record is the graded artifact. Submit the record generated from your completed simulation; you do not need to rewrite the experience as a separate reflection.

How this is graded

**What will be graded.** The instructor evaluates the quality of the release decision, how well your revised plan responds to the changed constraints, the tradeoff visible in the record, and the completeness and professionalism of the GitHub artifact. You are not graded on matching one hidden perfect release plan — there is no single correct release slice.

How this is graded

**Assignment details.**

- **Points:** 12
- **Submission type:** Website URL — a direct GitHub link to `docs/decisions/m3-product-owner-decision-record.md`
- **Graded by:** a three-criterion rubric (release decision reasoning, revision and tradeoff response, professional decision record)
